# Chronicle - Project Documentation

# Project Specification Summary
Project: Chronicle - A retro terminal-styled portfolio website.
Goal: Enhance the existing vanilla JS/CSS/HTML project by adding a build process, improving the CRT effect, updating content, cleaning code, and polishing the professional feel.
Audience: Potential employers, collaborators, tech enthusiasts.
Platform: Web (Desktop focus initially).
Key Features (Existing): Theming, filtering, project grid view, modals, sound effects, CRT effect toggle, static data.
Key Features (Planned): Build process (Vite/tsc+esbuild), Enhanced CRT effect, Real project content, Code cleanup, Professional polish.
MVP Approach: Implement foundational build process first, then iterate on features/cleanup.

# Architecture Summary
Stack: Vanilla JS (ES Modules), CSS3 (Variables), HTML5. Plan to introduce TypeScript and a build tool (Vite preferred, or tsc+esbuild).
Structure: Modular frontend code (js/, css/). Separate Node.js script for sound asset generation (`generate-sounds.js`).
Data: Static data in `js/data.js`.
State: Decentralized state via module variables (`filterState`, `graphState`), localStorage (preferences), and DOM classes.
Rendering: Dynamic HTML via JS (`render.js`, `modal.js`), extensive use of `innerHTML`. Text effects via `js/text-fx.js`.
Styling: CSS variables for themes, multiple effect/layout CSS files.
Key Modules: render, filter, project-grid, modal, theme, audio, crt-effect, stats, data.
Potential Issues: Data scalability, lack of tests, potential confusion between `graph.js` and `project-grid.js`.
